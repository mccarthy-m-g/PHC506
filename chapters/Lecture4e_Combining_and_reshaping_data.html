20.1 Introduction

dplyr makes data analysis reproducible, readable, and often easier!

  • Human readable: the function names describe the action being done
  • Piping: chain functions in a step-by-step way, rather than nesting

Many analytic tasks can be completed with mutate, filter, select, group_by, summarize and arrange. But sometimes you’ll need an expanded tool kit. Let’s look at a few more of the most useful functions.

20.2 Combining multiple data frames

20.2.1 left_join

Sometimes we need to use data available from multiple sources. To take advantage of the dplyr functions we used previously, we need data points of interest to be in the same data frame. The join family of functions helps here.

pt_char <- data.frame(
  pt = c("M.H.", "P.J.", "K.G.", "A.C."),
  age = c(77, 35, 56, 48),
  weight = c(65, 82, 70, 100),
  stringsAsFactors = FALSE
)
pt_char
#> # A tibble: 4 × 3
#>   pt      age weight
#>   <chr> <dbl>  <dbl>
#> 1 M.H.     77     65
#> 2 P.J.     35     82

#> 4 A.C.     48    100

pt_doses <- data.frame(

20.3 Tidyr: Long versus Wide Data

Even before we conduct analysis or calculations, we need to put our data into the correct format. The goal here is to rearrange a messy dataset into one that is tidy.

The two most important properties of tidy data are:

  1. Each column is a variable.
  2. Each row is an observation.

Tidy data is easier to work with, because you have a consistent way of referring to variables (as column names) and observations (as row indices). It then becomes easy to manipulate, visualize, and model.

Many tools in R will assume that your data is already tidy.

For more on the concept of tidy data, read Hadley Wickham’s paper here

20.3.1 Wide vs. Long Formats

“Tidy datasets are all alike but every messy dataset is messy in its own way.” – Hadley Wickham

Tabular datasets can be arranged in many ways. For instance, consider the data below. Each data set displays information on heart rate observed in individuals across 3 different time periods. But the data are organized differently in each table.

wide <- data.frame(
  name = c("Wilbur", "Petunia", "Gregory"),
  time1 = c(67, 80, 64),
  time2 = c(56, 90, 50),
  time3 = c(70, 67, 101)
)
wide
#> # A tibble: 3 × 4
#>   name    time1 time2 time3
#>   <chr>   <dbl> <dbl> <dbl>
#> 1 Wilbur     67    56    70
#> 2 Petunia    80    90    67
#> 3 Gregory    64    50   101

long <- data.frame(
  name = c(
    "Wilbur", "Petunia", "Gregory", "Wilbur", "Petunia", 
    "Gregory", "Wilbur", "Petunia", "Gregory"
  ),
  time = c(1, 1, 1, 2, 2, 2, 3, 3, 3),
  heartrate = c(67, 80, 64, 56, 90, 50, 70, 67, 10)
)
long
#> # A tibble: 9 × 3
#>   name     time heartrate
#>   <chr>   <dbl>     <dbl>
#> 1 Wilbur      1        67
#> 2 Petunia     1        80
#> 3 Gregory     1        64
#> 4 Wilbur      2        56
#> 5 Petunia     2        90
#> 6 Gregory     2        50
#> 7 Wilbur      3        70
#> 8 Petunia     3        67
#> 9 Gregory     3        10

Question: Which one of these do you think is the tidy format?

We often refer to these different structurs as “long” vs. “wide” formats. In the “long” format, you usually have 1 column for the observed variable and the other columns are ID variables.

For the “wide” format each row is often a site/subject/patient and you have multiple observation variables containing the same type of data. These can be either repeated observations over time, or observation of multiple variables (or a mix of both). In the above case, we had the same kind of data (heart rate) entered across 3 different columns, corresponding to three different time periods.

You may find data input may be simpler and some programs/functions may prefer the “wide” format. However, many of R’s functions have been designed assuming you have “long” format data.

20.3.4 tidyr::pivot_longer

The function pivot_longer() will turn a wide dataframe into a longer one by transforming the observation variables into a single variable. This is sometimes called “melting” your data, because it melts the table from wide to long. You might also see it called “gathering”.

Those data will be melted into two variables: one for the variable names, and the other for the variable values. Often, the terms “key” and “value” are used to refer to the variable names and variable values. You might also see the terms “name” and “value”.

?pivot_longer

billboard |>
  select(artist, track, starts_with("wk"))

Notice that we put 3 arguments into the pivot_longer() function:

  1. the name for the new column for the new ID variable (week),
  2. the name for the new observation variable (position),
  3. the names of the columns that we want to gather into one variable. (We could also have supplied the names of the columns we don’t want to re-shape, or the indices of these columns)

Notice that we don’t want to melt down columns 1 and 2, as these are considered “ID” variables.

We are nearly where we want to be. How many weeks did each song spend on the charts?

20.3.5 tidyr::pivot_wider

pivot_wider is the opposite of pivot_longer. It makes new columns using values in one column as the new column names, and the values in a second column as the new column values.

Usually, this means taking “tidy” data and making it “untidy”, but sometimes it is helpful to have data in this format for displaying in tables or graphs.

Here is an example of a tidy data set. It describes traumatic brain injury rates in the USA in 2014 as reported by the CDC. You can find more information about this data set here: https://github.com/rfordatascience/tidytuesday/tree/master/data/2020/2020-03-24
